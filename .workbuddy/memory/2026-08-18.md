## context-mode 源码分析（grill-me 驱动）

### 分析框架
- 焦点：Token 节省机制
- 深度：机制一致性核查 + 工程实践评估
- 范围：核心节省路径（executor + store + truncate + server 输出外部化）
- 交付：对话式分析

### 关键发现

**7 个独立 token 节省机制**：

1. **沙箱执行**（executor.ts）：声称"只有 stdout"，实际 stdout+stderr+echo 都返回。`combineExecOutput()` 拼 stderr，`buildExecuteEcho()` 前置最多 2000 字符代码 echo。
2. **输出外部化**（server.ts）：三层阈值——5KB（intent 搜索）、100KB（无条件索引）、5KB~100KB 盲区（原始 stdout 直接返回）。**最大节省缺口在 5KB~100KB 盲区**。
3. **FTS5 知识库**（store.ts）：双索引（porter+trigram）+ RRF 融合 + proximity reranking + fuzzy correction。代码块完整保留声明成立。
4. **截断工具**（truncate.ts）：UTF-8/surrogate 安全，但在主路径中使用有限。
5. **Fetch 预览**：3KB 单 URL / 384B 批量，最干净的节省机制。
6. **FloodGuard**：60s 窗口，3 次 softCap，8 次 block。按 agent 分桶。
7. **Session Snapshot**：声称"零截断零丢失"，实际是有损摘要+搜索指针。maxBytes 被忽略。

### 核心结论
Token 节省不是单一机制驱动，而是 **CLAUDE.md 路由规则 + 沙箱执行 + 输出外部化** 三层协同。路由规则是第一驱动力（强迫 LLM "Think in Code"），100KB 自动外部化是最后安全网。

### 关键文件路径
- `src/server.ts` — 4800+ 行，MCP 工具注册 + 安全 + 外部化 + analytics
- `src/executor.ts` — 多语言沙箱执行器（12 语言），100MB hardCap
- `src/store.ts` — FTS5 BM25 知识库，双索引 + RRF + proximity
- `src/truncate.ts` — 字节安全截断工具
- `src/security.ts` — 70+ 环境变量 denylist + 命令链拆分 + TOCTOU 防护
- `src/search/flood-guard.ts` — 按 agent 分桶的搜索节流
- `src/session/snapshot.ts` — XML 目录式快照恢复
