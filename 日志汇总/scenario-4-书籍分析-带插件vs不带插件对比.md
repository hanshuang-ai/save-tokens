## 六、插件适用性分析

### 本场景插件效果：**偏负向**

| 维度 | 效果 |
|------|------|
| 速度 | 基本持平（+0.4%） |
| 成本 | **大幅增加**（token +64.2%，新增输入 +73.9%） |
| 输出量 | 基本持平（+2.0%） |
| 输出效率 | 略升（+3.4%） |
| 缓存命中率 | 下降（92.0% → 85.9%，-6.6%） |

### 为什么插件在这个场景效果不好

1. **深度阅读+长文生成，核心耗时是模型生成**：插件无法加速生成长文的过程
2. **插件工具替代原生 Read 但效率更低**：不带插件用 Read 51次，带插件用 ctx_execute_file 15次 + ctx_execute 14次 + ctx_search 6次（合计36次插件工具），但新增输入反而增加 73.9%
3. **缓存命中率下降 6.6%**：带插件模式下上下文结构变化导致缓存效率降低
4. **本地处理增加**：中位数间隔从 0.06s 增至 0.72s，插件工具调用开销更大

### 插件适合的任务特征

- ✅ 大量重复性命令执行（批量处理日志、数据）
- ✅ 大文件/大数据集的搜索和过滤
- ✅ 有明确交付物的分析型任务
- ❌ 深度阅读+长文生成型任务：插件效果差，核心耗时是模型生成，反而增加 token 消耗

### 注意事项

- 带插件后 token 消耗 **+64.2%**（新增输入 +73.9%），成本大幅增加，是主要负面因素
- 速度基本持平（+0.4%），插件未带来速度提升
- 缓存命中率下降 6.6%，带插件模式下缓存效率降低
- 带插件用 36 次插件工具（ctx_execute_file 15 + ctx_execute 14 + ctx_search 6 + ctx_batch_execute 1）替代了原生 Read 51次，但成本更高
