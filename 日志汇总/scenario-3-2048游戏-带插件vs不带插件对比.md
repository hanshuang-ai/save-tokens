## 六、插件适用性分析

### 本场景插件效果：**中性偏负**

| 维度 | 效果 |
|------|------|
| 速度 | 提升（-12.5%，8分→7分） |
| 成本 | **增加**（token +20.1%） |
| 输出量 | 减少（-10.1%） |
| 输出效率 | **下降**（-37.7%） |

### 为什么插件在这个场景效果不佳

1. **从零生成型任务，没有批量操作空间**：不带插件只用了 3 次 Bash、5 次 Edit，插件的 `ctx_execute`（1次）和 `ctx_execute_file`（2次）替代空间有限
2. **核心耗时是代码生成**：最长调用 168s→88s 是因为拆分了调用，不是因为生成更快
3. **缓存读取大增 45.3%**：带插件后实际总输入增加 44.4%，但输出反而减少 10.1%，上下文冗余增加
4. **插件工具使用少**：仅 3 次插件工具调用，插件能力未充分发挥

### 插件适合的任务特征

- ❌ 从零生成型任务（无现有数据/代码可批量处理）
- ❌ 单次大输出生成（插件无法加速模型生成）
- ✅ 有大量现有文件/数据需要批量处理的任务
- ✅ 需要反复搜索、过滤、执行命令的探索型任务

### 注意事项

- 带插件后 token 消耗增加 20.1%，主要是缓存读取大增 45.3%
- 输出效率下降 37.7%，是因为实际总输入增加 44.4% 而输出减少 10.1%
- 速度提升 12.5% 主要来自拆分超长调用和更均匀的节奏，不是生成速度提升
